# 安全问题报告 / Security reporting

[中文](#中文) · [English](#english)

## 中文

请勿在公开 issue、讨论或 PR 中提交可利用的漏洞详情、真实 API Key、密码、Cookie、客户数据或未脱敏日志。

请发送邮件至 [support@metastonecorp.com](mailto:support@metastonecorp.com)，主题使用 `[SECURITY] searouter 漏洞报告`。如果仓库已启用 [GitHub 私密漏洞报告](https://github.com/MetastoneCorp/searouter/security/advisories/new)，也可使用该入口；入口不可用时直接使用上述邮箱，不要转为公开披露。

私密报告请包含受影响的 searouter 提交或镜像 digest、部署方式、复现步骤、影响范围及可选修复建议。请使用虚构数据复现；不要附带华为云登录指令中的密码或完整生产配置。

请先发送最小复现和影响说明；敏感材料的传输方式通过邮件另行确认。报告时注明版本或提交，维护者据此评估受影响范围；本项目目前不承诺固定响应时限或历史版本支持周期。修复进度通过私密渠道沟通，公开披露时间与报告者协调。

## English

Do not disclose exploitable details, credentials, customer data or unredacted logs in public issues, discussions or pull requests. Email [support@metastonecorp.com](mailto:support@metastonecorp.com) with the subject `[SECURITY] searouter vulnerability report`. [GitHub private vulnerability reporting](https://github.com/MetastoneCorp/searouter/security/advisories/new) is an alternative if enabled; otherwise use email, not a public issue.

Include the affected source revision or image digest, deployment method, reproduction steps, impact and any proposed fix in the private report. Reproduce with synthetic data; never include SWR passwords or production secrets.

Start with a minimal reproduction and impact description; arrange any sensitive transfer separately. Maintainers assess the affected versions from the report. No fixed response time or historical-version support window is currently promised. Discuss progress privately and coordinate public disclosure with the reporter.
